# 区域拾音

本文档是 `projects/area-pickup/` 的需求与方案入口。区域拾音的目标不是单纯“把声音录下来”，而是根据空间位置区分目标区域与非目标区域的声音。算法选型依赖场景、阵列几何、同步精度、声源分布和评估方式，因此先把可测量条件写清楚，再比较波束形成、声源定位或学习方法。

## 需要明确的需求

- **使用场景**：室内/室外、房间尺寸、混响、背景噪声、目标声源类型与运动情况。
- **拾音区域**：目标区域边界、距离、角度范围；区域外哪些声源需要抑制。
- **硬件**：麦克风型号、数量、阵列形状与坐标、单通道灵敏度/频响、声卡或采集板。
- **同步与采样**：通道是否共用时钟、采样率、位深、通道映射、时钟漂移和触发方式。
- **实时约束**：允许延迟、目标设备算力、运行时长、是否必须在线处理。
- **评价**：目标区语音可懂度/信噪比、区外抑制量、定位误差、延迟、不同位置和噪声条件下的稳定性。

## 系统拆分建议

1. **采集与校准**：多通道同步录音，确认通道顺序、极性、增益和阵列坐标。
2. **数据整理**：记录场景和声源位置，保留原始多通道音频及元数据；实验副本与公开/隐私边界分开。
3. **分析基线**：查看各通道波形、互相关、频谱和噪声底，验证阵列几何是否可用。
4. **算法实验**：选定明确基线后一次只改变一个因素，保存处理参数和输出。
5. **评价与复现**：固定测试位置和指标，比较未处理与处理结果，并记录设备、代码版本和环境。

## 当前状态与决策原则

当前目录是规划阶段，尚无阵列硬件、录音协议或算法实现的事实可供确认，因此不预设算法。`experiments.md` 作为逐次实验日志。开始实验前至少确定目标区域、麦克风坐标/通道数、同步方式和可重复的评价场景。

## 关键参数变更时要重新确认

| 变更 | 可能影响 | 需要记录或复核 |
| --- | --- | --- |
| 麦克风数量或阵列坐标 | 空间分辨能力、通道映射 | 坐标、通道顺序、阵列校准和基线结果 |
| 采样率或采集时钟 | 时间差估计、频率范围与同步误差 | 所有通道是否同钟，原始数据和算法参数是否同一采样率 |
| 目标区域边界或声源位置 | 目标/干扰定义与评价结果 | 测点位置、距离、角度、场景元数据 |
| 环境、混响、噪声条件 | 算法效果与可比较性 | 测试条件和评价指标，不跨不同条件直接比较结果 |
| 延迟和设备算力约束 | 可用算法与实时性 | 处理耗时、缓冲长度、端到端延迟 |
