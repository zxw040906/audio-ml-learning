## TDOA 与双麦克风延迟模拟

### 定义与符号约定

设声音到达麦克风 A、B 的时刻分别为 $t_A,t_B$，声源到两只麦克风的传播距离分别为 $r_A,r_B$，声速为 $c$。本模块约定：

$$
\tau=t_B-t_A=\frac{r_B-r_A}{c}
$$

因此，$\tau>0$ 表示 B 比 A 晚收到声音，$\tau<0$ 表示 B 比 A 早收到声音。采样率为 $f_s$ 时，采样点延迟 $k$ 与时间差的关系为：

$$
k=\tau f_s,\qquad \tau=\frac{k}{f_s}
$$

在 $f_s=16000\,\mathrm{Hz}$ 时，一个采样周期为 $1/f_s=0.0000625\,\mathrm{s}=0.0625\,\mathrm{ms}$；3 个采样点对应 $3/16000\,\mathrm{s}=0.1875\,\mathrm{ms}$。整数采样延迟的时间分辨率由采样率决定。

### `simulate_delay()` 的行为

[`spatial_utils.py`](spatial_utils.py) 中的 `simulate_delay(signal, delay_samples)` 支持带符号的整数和小数采样延迟，输出长度与输入相同，超出范围的部分补零。正值延后信号，负值提前信号。整数延迟通过切片移动；小数延迟通过 `np.interp()` 线性插值，近似实现 $y[n]=x[n-\delta]$。

线性插值不是理想带限分数延迟，会产生频谱误差。`doa.py` 另含 `simulate_delay_fft()`，采用零填充 FFT 相位平移作为仿真工具：

$$
Y(f)=X(f)e^{-j2\pi f\tau}
$$

其中 $\tau$ 是以采样周期为单位的延迟（数值上等于 `delay_samples`），`np.fft.fftfreq()` 生成归一化频率，`np.exp()` 生成相位因子，IFFT 回到时域。代码在信号两侧补零以减轻有限长 FFT 循环边界影响，并将 FFT 长度调整为奇数以避开偶数长度奈奎斯特频点的特殊情形。有限长随机信号仍有近似误差；它用于仿真实验，不等价于真实录音的物理传播模型。

一组周期正弦延迟实验的历史输出（用户提供）记录：线性插值最大幅度误差为 `0.02654462`，频域相位延迟为 `0.00000000`。该结果只描述该周期信号实验，不代表一般信号的误差上界。

## 双麦克风远场 DOA 几何

设阵列轴线连接 mic1 与 mic2，$\theta$ 从阵列正侧面（垂直于阵列轴线的方向）量起。远场声波可近似为平面波，两麦克风的路径差为：

$$
r_B-r_A\approx d\sin\theta
$$

结合 $\tau=(r_B-r_A)/c$ 和 $k=\tau f_s$，得到：

$$
\tau=\frac{d\sin\theta}{c},\qquad
k=\frac{d f_s\sin\theta}{c}
$$

$$
\theta=\arcsin\left(\frac{ck}{df_s}\right)
$$

$d$ 为麦克风间距（m），$c$ 为声速（m/s），$f_s$ 为采样率（Hz），$k$ 为 mic2 相对 mic1 的带符号延迟（采样点），$\theta$ 为方向角。按本模块的符号约定，$k>0$ 对应 $\theta>0$。反正弦输入必须在 $[-1,1]$；超出即代表输入延迟与该物理模型不相容，`tdoa_to_doa()` 会报错。角度范围为 $[-90^\circ,90^\circ]$，双麦克风线阵列无法单独区分阵列前后的镜像方向。

本阶段配置 `sample_rate = 16000 Hz`、`mic_distance = 0.1 m`、`sound_speed = 343.0 m/s`。因此连续物理延迟上限为 $df_s/c\approx4.6647$ 采样点。整数搜索使用 `ceil()` 得到 `max_lag = 5`；这只是包住连续范围的整数候选边界，±5 点本身不严格满足物理模型。

[`spatial_utils.py`](spatial_utils.py) 的 `tdoa_to_doa(delay_samples, sample_rate, mic_distance, sound_speed=343.0)` 将输入采样点换成秒，再计算 $c\tau/d$ 并调用 `np.arcsin()`，输出度数。`doa.py` 也包含理论角度到延迟、延迟估计与角度误差的仿真对照。这是远场几何基础验证，尚不代表真实语音或座舱定位验证。

## 普通互相关与整数延迟估计

### 互相关与符号

对两条信号采用如下互相关定义：

$$
R_{12}[k]=\sum_n x_1[n]x_2[n+k]
$$

在本项目的约定下，若第二路 `mic2` 比第一路 `mic1` 晚到 $k>0$ 个采样点，应使用：

```python
correlation = np.correlate(mic2, mic1, mode="full")
N = len(mic1)
lags = np.arange(-(N - 1), N)
peak_index = np.argmax(correlation)
estimated_delay = lags[peak_index]
```

`np.argmax()` 返回互相关数组中的**索引**，不是延迟本身；必须通过 `lags[peak_index]` 映射到带符号的采样延迟。交换麦克风顺序会改变延迟正负号，因此互相关输入顺序必须和符号约定保持一致。以上 lag 构造假定两路信号等长为 $N$，与本模块的输入检查一致。

### 麦克风几何给出的搜索范围

麦克风间距为 $d$ 时，两路传播距离差的绝对值不超过 $d$，因而：

$$
|\tau|\leq\frac{d}{c}
$$

换算成采样点后，整数搜索边界可设为：

$$
K=\left\lceil\frac{df_s}{c}\right\rceil
$$

例如 $d=0.1\,\mathrm{m}$、$f_s=16000\,\mathrm{Hz}$、$c=343\,\mathrm{m/s}$ 时，连续时间的最大延迟为 $d/c\approx0.0002915\,\mathrm{s}$，对应约 $4.66$ 个采样周期；整数搜索范围是 $-5$ 至 $+5$。代码通过布尔掩码选取候选 lag：

```python
max_lag = int(np.ceil(mic_distance * sample_rate / sound_speed))
valid_mask = np.abs(lags) <= max_lag
```

`ceil()` 为整数峰值搜索提供边界余量；它不表示边界上的每个整数延迟都满足严格的连续时间几何界限。例如 5 个采样点对应 $0.3125\,\mathrm{ms}$，大于上述 $0.2915\,\mathrm{ms}$。因此此处的掩码是一个保守的整数候选搜索范围，而不是对每个候选作连续物理可达性的精确判定。

[`calc_estimate_tdoa()`](spatial_utils.py) 当前复用 `estimate_normal_delay()` 的受限 lag 计算，并返回峰值延迟对应的秒数（`ms=True` 时返回毫秒）。

### 物理约束脉冲实验

[`sim_TDOA.py`](sim_TDOA.py) 构造长度为 30 的脉冲：目标在 `mic1` 的索引 5，第二路延迟 3 点后目标位于索引 8；随后在 `mic2[20]` 加入幅度为 3 的干扰脉冲。全范围互相关的最大峰对应 +15 点，加入麦克风间距约束后估计恢复为 +3 点。

该示例说明几何搜索范围可以排除不可能的远端峰值，但不能保证消除合法范围内的干扰峰。

## GCC-PHAT 原理与实现

[`spatial_utils.py`](spatial_utils.py) 中的 `estimate_phat_delay(mic1, mic2, max_lag)` 按“FFT → 互功率谱 → PHAT 归一化 → IFFT → 延迟搜索”的顺序计算，返回带符号的整数采样延迟。

### FFT 与互功率谱

对长度均为 $N$ 的两路信号，代码设置 $n_{\mathrm{fft}}=2N-1$ 并将两路信号补零后做 FFT：

```python
n_fft = 2 * N - 1
X1 = np.fft.fft(mic1, n=n_fft)
X2 = np.fft.fft(mic2, n=n_fft)
```

$2N-1$ 是两条长度为 $N$ 的序列完整线性互相关所覆盖的 lag 数量；采用该长度可避免把循环互相关的周期折叠误当成线性互相关。互功率谱按当前延迟符号约定定义为：

$$
G_{21}[m]=X_2[m]X_1^*[m]
$$

```python
cross_spectrum = X2 * np.conj(X1)
```

`np.conj()` 计算复共轭；`np.imag()` 则是提取复数的虚部，二者作用不同。互功率谱的乘法顺序与 lag 符号约定相连，不能随意交换。

### PHAT 归一化与回到延迟域

PHAT 将每个频点的互谱除以其幅度，主要保留相位信息：

$$
G_{\mathrm{PHAT}}[m]=\frac{G_{21}[m]}{\max(|G_{21}[m]|,\epsilon)}
$$

```python
phat = cross_spectrum / np.maximum(
    np.abs(cross_spectrum),
    1e-12,
)
```

这里 `np.abs()` 对复数返回幅度，`1e-12` 用来避免分母为零。对幅度非零的频率分量，归一化后的幅度为 1；近零分量由下限保护。

随后 IFFT 将结果变回延迟域。IFFT 的原始索引排列中，负延迟位于数组尾部，因此把负 lag 段移到前面：

```python
gcc = np.fft.ifft(phat).real
gcc = np.concatenate((gcc[-(N - 1):], gcc[:N]))
lags = np.arange(-(N - 1), N)
```

此时 `gcc` 与 `lags` 一一对应。代码再通过 `np.abs(lags) <= max_lag` 选取搜索范围，并在有效段中用 `np.argmax()` 找峰值。调用方必须确保 `max_lag` 与信号长度相容；与受限普通互相关不同，`estimate_phat_delay()` 本身没有把 `max_lag` 限制到 `N-1`。

### 基础正确性观察

提供的基础验证使用 64 点随机宽频信号，并将第二路延迟 +3 点：GCC-PHAT 估计为 +3；PHAT 归一化后前几个非零频率分量幅度为 1。记录的无噪声峰值约为 0.9898，加入噪声系数 0.5 后峰值约为 0.5348，估计仍为 +3。峰值高度会受信号和噪声影响，不能直接当作估计正确率。

### 亚采样点与连续峰值搜索

`estimate_phat_delay(..., subsample=True)` 在整数相关峰及左右邻点上拟合局部抛物线。令三点值为 $y_{-1},y_0,y_{+1}$，顶点相对整数峰的偏移为：

$$
\delta=\frac{y_{-1}-y_{+1}}{2(y_{-1}-2y_0+y_{+1})},\qquad
\hat{k}=k_0+\delta
$$

代码中的 `parabolic_peak_offset()` 实现此式，边界峰或分母接近零时回退到零偏移。它是三点局部近似，不等同于对连续 GCC-PHAT 函数做精确搜索。

`estimate_phat_delay_precise()` 则计算 PHAT 频谱并搜索连续延迟相关函数。其导数形式可写为：

$$
R'(\tau)=\frac{1}{L}\operatorname{Re}\sum_m (j2\pi f_m)G_{\mathrm{PHAT}}[m]e^{j2\pi f_m\tau}
$$

代码中 `omega = 2j * np.pi * frequency`、`weights = omega * phat` 与 `np.exp(omega * delay)` 对应频率权重和连续相位项。整数粗定位后，二分法寻找导数由正变负的局部驻点。若不能建立端点导数异号区间，则退回粗网格；复杂多峰时不保证全局最优。

接口支持 `mode="auto"`（整数+二分失败时才低倍率过采样回退）、`"integer"`（不启用过采样）和 `"upsampled"`（强制过采样粗定位后再二分）。过采样通过频谱居中补零构造间隔为 $1/\mathrm{upsample}$ 采样点的网格；倍率需为不小于 3 的奇数。`return_info=True` 会额外返回 `integer_refined`、`upsampled_refined`、`integer_grid` 或 `upsampled_grid` 状态。默认 `estimate_phat_delay()` 仍返回整数；`subsample=True` 返回抛物线估计。数值搜索精度不代表真实 TDOA 精度。

`doa.py` 有 `main()`（多延迟与 DOA 对照）、`noise_experiment()`、`noise_failure_experiment()` 等函数；模块直接运行时仅调用最后一个。实验工具函数定义在 `spatial_utils.py`，历史 Monte Carlo 主脚本位于 `gcc_phat.py`，不要混淆实现位置与运行入口。

以下为用户提供的历史实验输出摘要，不是本次重跑结果。噪声实验以真实延迟 `2.3324` 采样点、独立白噪声和 30 次重复比较抛物线与精确估计；失败分析以 256/1024 点、0/-5/-10/-15 dB、每条件 100 次为配置。历史记录显示低 SNR 下会出现整数粗定位错峰与超过 1 采样点的严重误差；自动回退次数不等于正确率。

## 普通互相关与 GCC-PHAT 的 Monte Carlo 对比

### 实验模型与评价指标

每次实验生成宽频高斯信号和两路独立高斯噪声：

$$
x_1[n]=s[n]+\alpha v_1[n]
$$

$$
x_2[n]=s[n-3]+\alpha v_2[n]
$$

其中 $s[n]$、$v_1[n]$、$v_2[n]$ 为标准正态随机信号（两路噪声相互独立），真实延迟为 +3 点，采样率为 16 kHz，麦克风间距为 0.1 m。每种条件重复 100 次，使用 `np.random.default_rng(42)`。$\alpha$（代码中的 `noise_level`）是噪声幅度系数，不是以 dB 表示的 SNR。每一轮生成的同一对 `mic1`、`mic2` 同时送入普通互相关与 GCC-PHAT，保证算法间比较使用相同输入。

平均绝对延迟误差（MAE，单位为采样点）和整数延迟完全正确率分别为：

$$
\mathrm{MAE}=\frac{1}{M}\sum_{i=1}^{M}|\hat{k}_i-k_{\mathrm{true}}|
$$

$$
\mathrm{Accuracy}=\frac{1}{M}\sum_{i=1}^{M}\mathbf{1}(\hat{k}_i=k_{\mathrm{true}})
$$

MAE 越小越好，表示平均误差大小；正确率越高越好，表示整数延迟完全匹配比例。它们关注不同表现，可能给出不同的算法排序。

### 结果解释与适用边界

在本次合成信号模型和随机实验范围内，增加观测窗口通常明显改善估计稳定性；强噪声下短窗口误差较大，延长窗口可累积更多相关信息。GCC-PHAT 在这些白噪声条件下没有表现出普遍优势，普通互相关在多数测试条件中不逊于 GCC-PHAT。PHAT 强调相位信息，但强噪声也会破坏相位可靠性，所以它不保证所有条件下性能更好。

这些结果来自人工宽频信号，不能直接推断真实语音或汽车环境下的表现；每个条件仅 100 次随机试验，结论仅适用于所列配置和实验范围。长窗口可能增加估计稳定性，也延长观测时间；实际系统还需权衡响应速度以及声源在观测期间移动的影响。

## 利用物理约束优化普通互相关

原先的 `np.correlate(mic2, mic1, mode="full")` 会计算全部 $2N-1$ 个延迟，再筛选物理范围。对 $N=16000$（1 秒、16 kHz）而言，需要生成 31999 个 lag 候选，而此处物理整数搜索范围只有 $-5$ 至 $+5$ 共 11 个候选。

[`estimate_normal_delay()`](spatial_utils.py) 现在直接遍历合法 lag，并用 `np.dot()` 计算对齐片段的乘积和。设两路信号长度均为 $N$：

```python
# k > 0：mic2 比 mic1 晚 k 点
np.dot(mic1[:N-k], mic2[k:])

# k < 0，令 q = -k：mic2 比 mic1 早 q 点
np.dot(mic1[q:], mic2[:N-q])

# k == 0
np.dot(mic1, mic2)
```

函数把 `max_lag` 截到 `N - 1`，随后只计算 `[-max_lag, max_lag]` 中的候选。对固定且较小的候选数 $K$，计算量从完整直接互相关的大致 $O(N^2)$ 降至约 $O(NK)$。这利用已知物理约束减少无效计算，没有改变每个所计算延迟位置上的互相关数学定义。相同 Monte Carlo 实验记录中优化前后的普通互相关 MAE 和正确率一致；目前没有严格计时数据，因此不报告具体耗时或加速倍数。

## NumPy 知识点与代码对应

- `np.correlate()` 计算完整普通互相关；`np.arange()` 生成带符号 lag；`np.argmax()` 找到峰值数组索引，再通过 lag 数组映射成延迟。
- `np.abs()` 用于取 lag 绝对值做掩码，也用于计算复数幅度；`np.ceil()` 将连续物理边界转成整数搜索上界；布尔掩码选出允许的候选延迟。
- `np.fft.fft()`、`np.conj()`、`np.maximum()`、`np.fft.ifft()`、`np.concatenate()` 分别对应 GCC-PHAT 的频谱计算、复共轭、分母下限、回到延迟域和负/正 lag 重排。
- `np.dot()` 对齐两路信号片段并计算乘积和；`np.random.default_rng()` 建立可复现随机数生成器；`np.asarray()` 将估计列表转成数组；`np.mean()` 计算 MAE，以及布尔正确判断的平均比例。

### 当前算法方案

当前 `spatial_utils.py` 的 `estimate_phat_delay_precise()` 首先计算 PHAT 频谱，在受限整数 lag 上寻找相关峰作为粗定位；随后用连续相关函数的一阶导数，在粗峰附近执行二分搜索局部驻点。`auto` 模式只有整数粗定位后的导数搜索不能建立有效区间时，才调用低倍率过采样 IFFT 重新定位并再次尝试二分。该导数条件通过只表示局部数值搜索能够执行，不表示选中了真实声源峰值。

函数签名及默认参数如下：

```python
estimate_phat_delay_precise(
    mic1,
    mic2,
    max_lag,
    upsample=5,
    mode="auto",
    tolerance=1e-5,
    max_iterations=25,
    return_info=False,
)
```

`mode` 支持三种取值：`"auto"` 先整数粗定位与二分，失败时才过采样回退；`"integer"` 只做整数粗定位与二分；`"upsampled"` 强制用过采样网格粗定位，再执行二分。`upsample` 是可配置的奇数倍率（至少为 3，默认 5），不是固定 3 倍；`mode="auto"` 可用 `upsample=None` 禁用回退。`tolerance` 是二分区间宽度容差，单位为采样点；`max_iterations` 是最大迭代次数。

默认只返回带符号的浮点采样延迟。`return_info=True` 返回 `(延迟, 状态)`，状态为 `integer_refined`、`upsampled_refined`、`integer_grid` 或 `upsampled_grid`。后两者表示没有找到满足导数条件的局部细化结果，返回相应粗网格位置。

目前同时保留旧接口：`estimate_phat_delay(..., subsample=False)` 返回整数延迟，`subsample=True` 返回三点抛物线插值结果。精细搜索受噪声、混响、多峰和局部单峰假设影响；数值容差不等于实际估计准确度，也没有声源峰身份判别机制。

### 已确认的问题

- **问题 A：抛物线插值的系统性偏差。**真实相关峰不一定是理想抛物线形状，因此三点插值即使在较长窗口下也可能有稳定偏差。
- **问题 B：低倍率过采样的局限。**过采样提高相关函数的数值搜索密度，不一定提高实际延迟估计准确度，也不保证选中正确声源峰。
- **问题 C：自动回退触发机制不足。**当前回退主要判断局部导数搜索能否执行，而不是峰值是否来自真实声源。1024 点、-10 dB 下整数错峰率为 42%、严重误差率为 25%，但回退次数为 0，说明严重定位错误可能发生而自动模式不触发回退。
- **问题 D：峰值可信度尚不可靠。**`peak_margin` 和 `normalized_peak` 在部分条件下有区分能力，但极低 SNR 下不同结果类别的均值可能接近。目前没有证据证明仅用一个固定阈值就能可靠识别错误峰值。

### 恢复研究时的执行路线

1. 运行当前 `doa.py` 的低 SNR 回归实验，确认上述历史基准能否复现。
2. 阅读 `estimate_phat_delay_precise()` 的整数粗定位、导数搜索和自动回退流程。
3. 在不依赖真实延迟做在线判断的前提下研究相关峰可信度。
4. 对比主峰与次峰、峰值优势、峰形和跨帧一致性等信息。
5. 若可信度特征无法区分错误结果，优先研究多帧一致性和多候选峰，不以单纯提高过采样倍率作为主要方向。
6. 明确评价指标，包括严重错误检测召回率、误报率，以及新策略介入后的 TDOA MAE。
7. 与整数 + 二分基准使用相同输入和相同噪声条件进行成对对照。
8. 测量完整处理耗时，并结合未来汽车座舱实时系统的帧长、延迟和计算成本评估。
